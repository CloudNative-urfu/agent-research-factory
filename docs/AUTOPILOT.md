# Автопереход с проверкой ценности улучшений

Автопилот не меняет уже работающий проход. Он ждёт завершения кампании и независимой
critique, проверяет хеши снимка и запускает две отдельные сессии Claude:

1. `IMPROVEMENT-BRAINSTORM.md` — COSTAR-промпт исполнителя: улучшение текущего решения,
   пользователь/процесс, причинный механизм пользы, сравнение способов улучшения,
   1–5 проверяемых задач. Альтернативы — только крайняя мера.
2. `IMPROVEMENT-REVIEW.md` — COSTAR-промпт критика: независимая оценка проблемы,
   дополнительной ценности, доказательств и критериев следующего прохода.

`proceed` запускает следующую ревизию только с выбранными критиком ID задач.
`revise` возвращает план исполнителю (не более двух возвратов). `pivot`, `stop`,
`blocked` или исчерпание возвратов ставят цепочку на паузу; другой проект автоматически
не создаётся. Пока решения `proceed` продолжаются, фиксированного числа ревизий нет.
Само наличие критики не считается разрешением продолжать.

## Конфигурация

`~/.local/share/research-autopilot/darp/config.json`:

```json
{
  "campaigns": "/home/geekiot/.local/share/research-campaigns",
  "initial": "darp-revision-4",
  "prefix": "darp-revision-",
  "next_number": 5,
  "enabled": true,
  "min_free_bytes": 1073741824
}
```

Команда: `research-factory autopilot ~/.local/share/research-autopilot/darp`.
Home Manager экспортирует шаблон `research-autopilot@.service` без `Install.WantedBy`.
Запуск конкретного экземпляра задаётся в конфигурации хоста:

```nix
home-manager.users.geekiot.systemd.user.targets.default.Unit.Wants = [
  "research-autopilot@darp.service"
];
```

Не включайте сам шаблон через `Install.WantedBy`: Home Manager может попытаться
запустить его без имени экземпляра. После активации экземпляр можно запустить вручную
через `systemctl --user start research-autopilot@darp.service`.
Для работы до входа пользователя нужен ранее настроенный linger.

`state.json` автопилота хранит текущую кампанию, следующий номер, состояние и причину
паузы. `assessments/<следующая-ревизия>/` содержит входы, промпты, журналы обеих ролей,
планы, ответы критика и итоговое решение. На `waiting_limit` смотрите также state.json
оценки: лимит Claude пережидается с сохранением срока, как в основном контроллере.

## Сохранность и восстановление

- Предыдущие кампании и снимки не удаляются. Новая ревизия получает проверенную
  baseline-копию, рабочую копию и происхождение решения в autopilot.json.
- Создание новой ревизии публикуется переименованием подготовительного каталога.
  Повтор после сбоя не создаёт дубль и не перезаписывает чужую папку.
- После перезагрузки автопилот возобновляет текущую кампанию или сохранённую оценку.
- Недостаток диска, повреждённый снимок, отсутствие завершённой критики, невалидная
  сдача после трёх попыток или блокировка текущей кампании останавливают переход.
- Промпты запрещают API-эксперименты Qwen на стадии оценки. Для новых доработок
  бюджет фиксируется в brief; это инструкция агентам, а не новый сетевой ограничитель.
- Автопилот не создаёт коммиты и не делает push.

Остановка автопилота: `systemctl --user stop research-autopilot@darp.service`.
Уже запущенная доработка продолжит работу; для остановки самой кампании остановите
её `research-campaign@<имя>.service` отдельно.

После осмысленной паузы `pivot/stop/blocked` решение принимает оператор. Не сбрасывайте
паузу вслепую: сохраните исходное решение и исправьте причину перед повторной оценкой.
