# Запуск исследовательской фабрики

Исследовательская постановка: [agent-defense-and-continuity.md](agent-defense-and-continuity.md).

Реализация и полная инструкция:
[nix-dots/modules/aspects/agent-harness/_research/README.md](nix-dots/modules/aspects/agent-harness/_research/README.md).

## Зафиксированные решения

- Пять реализаций с нуля; память содержит знания и доказательства, не старый код.
- Исследователь выбирает подход внутри темы; LoRA, домен и мониторинг не предписаны.
- Обязательный независимый критик и внешняя команда проверки MVP.
- После выбора кандидата — новый подтверждающий эксперимент.
- Состояние и архив контролирует программа, а не самооценка агента.
- Новая итерация после критики автоматическая; провал гипотезы требует поиска лучшей идеи.
- Бюджет, ошибки API, отсутствие ресурса и отсутствие полезного результата различаются.

## Короткий путь

1. Применить собранный NixOS-конфиг `book` и авторизовать исследовательские профили.
2. Создать кампанию через `research-factory init ... --brief ... --config campaign.example.json`.
3. Указать модель исследователя в созданном `campaign.json`.
4. Настроить ключ и запустить OpenRouter-прокси по инструкции ниже.
5. Выполнить `research-factory doctor ... --live`, затем `research-factory run ...`.

Для длительного фонового запуска предусмотрен user unit `research-campaign@<имя>`.
Остановка и восстановление описаны в полной инструкции. Применение NixOS,
авторизация и настройка прокси выполняются один раз перед автономной работой.

## Куда вставить ключ OpenRouter

После применения NixOS-конфигурации:

```sh
install -m 600 ~/.config/agent-research/openrouter.example.env ~/.config/agent-research/openrouter.env
```

Открой `~/.config/agent-research/openrouter.env` своим редактором и замени
`REPLACE_WITH_YOUR_OPENROUTER_KEY` на ключ. Это единственное место для ключа
экспериментальной модели. Повторно команду `install` не выполняй — она заменяет файл.
Файл не находится в репозитории и не попадает в Nix store.

```sh
systemctl --user daemon-reload
systemctl --user start research-llm-proxy
curl --fail http://127.0.0.1:8787/health
research-llm-proxy --check
```

`/health` подтверждает только запуск прокси. `--check` делает платные запросы
генерации, JSON, tool calling и streaming; выводит только результаты проверок.
При смене ключа: `systemctl --user restart research-llm-proxy`.
Для автозапуска при входе: `systemctl --user add-wants default.target research-llm-proxy.service`.

В `campaign.example.json` уже заданы URL и модель. Старые кампании не изменяются:
в их `campaign.json` нужно заменить `experiment` на объект из примера.
Удали прежние `RESEARCH_LLM_*` из окружения запуска, если задавал их: они имеют
приоритет над файлом кампании. Для нового подключения они не нужны.

Прокси слушает только `127.0.0.1:8787`, принимает запросы локальных процессов
без отдельного ключа, передаёт ключ OpenRouter только upstream. Маршрут фиксирован:
`qwen/qwen3.5-9b`, провайдер `together`, без fallback. Неподдерживаемые параметры
дают ошибку вместо молчаливого игнорирования. Тела запросов и ответов не журналируются.
Прокси сохраняет HTTP-ошибки, `Retry-After`, SSE, usage/cost и не повторяет запросы.
При разрыве потока не добавляет фиктивный `[DONE]`; эксперимент должен считать такой
ответ незавершённым. Облачные и локальные результаты учитываются раздельно.

Авторизация исследователя и критика по-прежнему отдельная: ключ OpenRouter для
экспериментальной Qwen не авторизует OpenCode и Claude Code.

## Продолжение завершённой кампании

```sh
research-factory extend ~/.local/share/research-campaigns/defense --cycles 10 --swap-agents
systemctl --user start research-campaign@defense
```

`--cycles` задаёт общий бюджет, не число дополнительных циклов. Команда работает
только для завершённой кампании, использует блокировку контроллера, архивирует
прежние state/config/FINAL/selection/doctor и подтверждения в `history/after-*`.
Снимки, результаты, критика и попытки существующих циклов сохраняются; следующий
цикл получает их память. `--swap-agents` меняет исполнителей и модели местами.
Без этого флага роли сохраняются. Новый итог будет сформирован после новой серии.
Если установленная версия ещё не содержит `extend`, ту же операцию можно выполнить:
`python3 nix-dots/modules/aspects/agent-harness/_research/factory.py extend ...`.

## Локальный монитор

`http://127.0.0.1:8788` — состояние, цикл/стадия, модели, свежесть файлов,
прогресс, протокол, результаты, критика, квитанции и последняя проверка doctor.
Автообновление каждые 5 секунд. Страница только читает разрешённые артефакты;
тексты отображаются как текст, без выполнения HTML из отчётов.

Запуск без установки, Nix и дополнительных зависимостей (из корня проекта):

```sh
python3 research-dashboard/dashboard.py ~/.local/share/research-campaigns/defense
```

Для другой кампании передай её путь; другой порт — `--port 8789`.
Остановка — Ctrl+C в терминале сервера.
Нет новых записей не означает зависание: API и команды могут выполняться долго.
Квитанции и файлы отображают сохранённое состояние, а не непрерывный поток мысли модели.
