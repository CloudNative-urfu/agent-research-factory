# Методология

Цель — исследовать защиту агента с сохранением полезной работы, а не добиться
положительного результата любой ценой. [Исходная постановка](source/agent-defense-and-continuity.md).

V1 последовательно выполняет research → plan → build → experiment → report →
verify → review, затем confirm. V2 добавляет раннюю независимую критику и пилот:

```
research → idea_review → pilot_plan → pilot → pilot_review
         → plan → build → experiment → report → verify → review → confirm
```

На ранних проверках допустимы ограниченный revise и отсев `screened_out`.
Пилот проверяет интерфейс, необходимость модели, отличие механизма и выполнимость
бюджета. Он не является подтверждением эффективности. Неудачная гипотеза —
допустимый результат; инфраструктурная ошибка — не её опровержение.

## Сопоставимость

- Пул идей охватывает минимум три среды и два семейства защит.
- Сравнение включает сильные простые решения и применимые готовые гвардрейлы.
- Для каждого сценария нужны многошаговые действия, наблюдаемые эффекты,
  границы доверия, независимый oracle и отрицательные контроли.
- Источники и причины несовместимости проверяет критик по первоисточникам.
- Данные разработки не переименовываются в независимое подтверждение.
- Изменение маршрута/модели — изменение условий эксперимента.

Пилот: максимум 100 запросов / 1800 секунд. Пилот и основной эксперимент вместе:
максимум 600 запросов / 14400 секунд, включая retry и подтверждающие измерения.
Отчёт, реализация и литературный обзор не входят в эти четыре часа. Контроль
работает через research-experiment; обход прямым HTTP запрещён инструкциями,
но не предотвращается сетевым firewall.

## Независимость

Исследователь и критик работают в отдельных сессиях; критик получает неизменяемую
копию материалов. Его рабочая область может содержать собственные проверки.
Это не означает, что вся sandbox критика read-only. Разные модели усиливают
разделение; две роли Claude не обеспечивают кросс-модельную независимость.

## Границы текущей реализации

HTTP 200 не гарантирует удачную генерацию. Исполнитель различает completed,
truncated, refused, failed и unknown. Сетевой обрыв не обеспечивает exactly-once.
Кеширование общего префикса не гарантирует cache hit; факт проверяется по usage.
Снимки исключают runtime-каталоги и нерегулярные объекты. Поэтому доказательства
должны лежать в обычных файлах artifacts/, а не в tmp/venvs.

актуальную реализацию, инструкции этого каталога и зафиксированные версии.
