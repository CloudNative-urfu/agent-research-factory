# Ручное формирование истории

Машиночитаемый план: `commit-plan.json`. Для каждой записи указаны задача,
автор, сообщение, пути и условный день реконструкции. Это импорт готовой системы:
промежуточные коммиты отражают тематические пакеты, а не TDD-разработку с нуля.
Полностью работоспособным должен быть итоговый набор.

Перед созданием каждого коммита участник проверяет diff. Пример:

```sh
git add -- LICENSE .gitignore
git diff --cached --check
git diff --cached
git -c user.name=geekiot-hub -c user.email=geekiot@proton.me \
  commit --author='geekiot-hub <geekiot@proton.me>' -m 'chore: establish MIT project baseline'
```

Следуй точным спискам файлов из плана; не используй `git add .` для каждого шага.
После всех коммитов:

```sh
git status --short
git log --format='%h %an <%ae> %s'
git push -u origin main
```

В плане даты 18–23 октября — реконструированная шкала, указанная в документации.
Рекомендуется сохранять фактические даты Git-коммитов: так авторство и время
выделения не смешиваются с датами условных этапов. Создание/отправка коммитов
в этой поставке оставлены участникам команды.
